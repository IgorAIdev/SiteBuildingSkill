# Поиск и нейросети (SEO, GEO) — что нужно и чем меряется

Слово заказчика 28.09.2026: «мы всё делаем ещё и с позиции лучшего SEO/GEO»
и «записывай в скилл, чтобы в следующий раз не повторять». Поэтому здесь не
советы, а список: у каждого пункта — где он в коде и какая проверка его
держит. Пункт без проверки — долг, он помечен и закрывается первым.

## Границы профиля и актуальность

Таблица описывает текущую CBD-витрину и её проверки, а не обязательную
архитектуру любого магазина. Отдельные страницы силы/меры сохраняются в этом
профиле. Google поддерживает и одно-, и многостраничные варианты: выбрать
модель по каталогу, согласовать URL, canonical и `ProductGroup`, не менять SKU
лишь ради адреса. [Документация вариантов](https://developers.google.com/search/docs/appearance/structured-data/product-variants).

FAQ добавляется для полезных ответов; количества ниже — договор существующего
содержания. Разметка `FAQPage` не обязательна для каждого магазина и не обещает
видимость в ответах нейросетей. Google прекратил FAQ rich results 07.05.2026;
источник, сверенный 06.10.2026: [Search Central updates](https://developers.google.com/search/updates).
Имеющаяся семья `faqPage` проверяет договор текущей витрины, а не универсальное
условие допуска в поиск. В новом проекте назначить только применимые проверки.

| что | как устроено | чем меряется |
|---|---|---|
| **Страница на каждую продаваемую вещь** — сила и мера товара, а не параметр адреса | отдельный товар на силу и меру; линейка — соседи той же марки и имени без меры (`lib/source/line.ts`), выбор — ссылками на соседей (И503) | `tests/line.test.ts` |
| **Своё имя страницы** — `<title>` не повторяет чужой на том же языке | `toMetadata`; у товара линейки — имя и мера (`titleOf`) | `check:seo`, семья `title` |
| **Своё описание** — meta description не повторяет чужое | у товара линейки описание начинается с имени и меры | `check:seo`, `description` |
| **Один h1, свой у каждой страницы** — поиск и нейросеть берут его именем страницы | h1 товара — `titleOf`, у полки — имя полки, у главной — обещание героя | `check:seo`, `h1` (И504) |
| **Лестница заголовков** — h2 ниже h1, без пропусков уровней, раздел не громче имени | роли текста строителя шкал; имя товара — `--prodhead-*` | `check:craft`, `ladder`; `check:design`, `headRole` |
| **h2 — словами покупателя** («Состав», «Как принимать», «Доставка и оплата»), не «Раздел», не повтор h1 | заголовки разделов карты — из данных вида товара (`standardDetails`) | глазом при ревью; проверки пока нет — **долг** |
| **FAQ там, где полезен покупателю** — полка, товар, доставка, оплата | блок `faq`; при выбранном `FAQPage` разметка из тех же видимых данных | `check:seo`, `faqPage` — контракт текущего профиля |
| **Вопросов столько, сколько нужно странице** — главная 6–8, товар 5–8, полка 5–10, под статьёй от трёх; одним списком не больше десяти | `references/blocks.md`, «Сколько вопросов» (И719) | `tests/content.test.ts` витрины |
| **Разметка товара** — Product, марка, SKU, цена только настоящая, группа вариантов | `lib/ld.ts`: `inProductGroupWithID` у линейки, цена при `PRICES_ARE_REAL` | `check:seo`, `ld`, `sample` |
| **Крошки** — путь от главной, разметкой `BreadcrumbList` | `Breadcrumbs`, `breadcrumbLd` | `check:seo`, `ld` |
| **canonical на себя, hreflang на все языки** | `toMetadata` | `check:seo`, `canonical`, `hreflang` |
| **Карта сайта обещает только живые страницы** | `app/sitemap.ts` из `productIds` | `check:urls` |
| **Язык рынка у всего, что читает машина** | перевод по ключу на сборке | `check:seo`, `market` |
| **Картинка с alt, факт — текстом** (нейросеть цитирует текст, не картинку) | `alt` у снимков, сила и мера строкой фактов | `check:seo`, `alt` |

## Порядок, когда появляется новая поверхность

Для написания самих текстов использовать `seo-content` (копия из
`site-building/assets/seo-content/SKILL.md`), включая данные рынка, бриф,
редакционную проверку и локализацию. Таблица выше отвечает за технический
контракт текущего магазина, а не заменяет процесс написания текста.

1. Назвать, что на ней продаётся или объясняется, — у этого своя страница?
2. Имя, h1 и описание — из данных, уникальные на языке.
3. Вопросы покупателя на этой странице — полезный FAQ; разметка по принятому контракту.
4. Прогнать `check:seo` и `check:urls` на собранной витрине; новая дыра —
   строка в таблице выше и проверка к ней.
