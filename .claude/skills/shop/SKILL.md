# Интернет-магазин

> Слой набора над вёрсткой: `craft` — как устроен ЭКРАН, `code` — КОД, этот — МАГАЗИН:
> что такое товар, где живёт его цена, чем полка отличается от страницы, за что
> магазин отвечает по закону. Всё здесь заведено дефектом витрины и почти всё
> меряется.

## Что здесь и что не здесь

| увидел | иди к |
|---|---|
| товар, вариант, полка, фильтр, корзина, касса, кабинет, страницы магазина, разметка о товаре | сюда |
| отступ, раскладка, ширина, доступность, знак; полоса и окно согласия на cookie | `craft` |
| цвет, размер и ритм | `palette`, `scale` |
| повтор в коде, состояние, склад браузера, границы `lib/` | `code` |
| «что дальше», «какой этап», «готово ли к сдаче» | `stages` |
| тексты и заголовки по согласованной задаче | `seo-content` (в наборе — `site-building/assets/seo-content/SKILL.md`); неизвестные факты — уточнить, не выдумывать |
| режим, рынок, ассортимент, применимое право | `site-building/references/ecommerce.md`, `compliance.md` |
| деньги, снимок корзины, промокод, модель вариантов, шаги кассы — общее для движков | `site-building/references/commerce-patterns.md` |
| реквизиты, цены, документы, снимки, условия | источники магазина и владелец; дефект данных — `docs/open.md` |

**Профили.** Этот файл — договор торгового профиля набора: общие торговые инварианты и
решения существующей витрины. Помечено «профиль витрины-образца» — вкус владельца на
шаблоне (числа, виды, слова), «профиль CBD» — только для магазина CBD, «профиль
рынка» — право и слова одной страны (`references/profile-market-ro.md`,
`references/profile-market-bg.md`). Для чужого проекта профиль не обязателен:
неприменимость записывается с причиной. Право проверять по первоисточникам; правила
целевого проекта старше умолчаний профиля; различать норму, инженерный принцип,
договор магазина и гипотезу.

## Порядок работы

1. **Прочитать `CLAUDE.md` проекта.** Он старше кода.
2. **Назвать профиль.** Рынок, ассортимент, режим — по `site-building` (`ecommerce.md`,
   `compliance.md`); применимый профиль рынка и CBD — из таблицы справочников ниже. Новый
   рынок: витрина строится на английском, профиль рынка (`profile-market-<код>.md` по
   образцу ro/bg) и что можно продавать — к завершению (`site-building`,
   `template-storefront.md`, «Новый рынок на шаблоне»); до текстов категорий и товаров —
   досье рынка по `seo-content` (`skills/site-building/assets/seo-content/references/research.md`). Страница категории: что на ней —
   `references/pages.md` и `catalog.md`, вид — бриф `docs/design/<поверхность>.md`.
3. **Найти, где факт живёт, прежде чем его печатать.** `lib/` — источник; витрина
   спрашивает. Есть функция, которая это уже решает, — звать её.
4. **Правка вида — дизайнерскими скиллами**, порядком из `CLAUDE.md`, «Дизайн делается
   дизайнерскими скиллами». Части витрины (фильтр, карточка, шторка) предлагаются
   заказчику меню вариантов на этапе изготовления, все сразу, без порогов; за основу —
   часть шаблона.
5. **Сделать правку.** Дефект, показанный в одном месте, ищется во всех остальных тем же
   признаком — до правки.
6. **Прогнать проверки** (ниже): `npm test`, `check:code`, `check:css`; после сборки —
   `check:seo`, `check:urls`, `check:counters`. Долг не должен вырасти.
7. **Показать отрисованным — и на телефоне:** корзина, крошки и меню ломаются там.
8. **Записать правило**, если родилось: закон — сюда, в свой раздел, одним абзацем;
   разбор с дефектом — в `references/<тема>.md`; правило — в проверку; решение
   заказчика — в `docs/decisions.md`; открытый вопрос — в `docs/open.md`. Журнал
   `docs/rules.md` заморожен 10.10.2026 — новых номеров нет.

```
npm test               # согласованность данных, текст полок, формула силы
npm run check:css      # twoTruths — факт рядом с идентификатором, валит сразу
npm run check:code     # glued, deadLink, translated, jumpBack, contactScheme
npm run check:seo      # market, faqPage, h1, ld, canonical, hreflang — по собранному out/
npm run check:urls     # обещанное открывается, открытое обещано — по собранному out/
npm run check:counters # нажатием: счётчики, строка покупки, «в корзину» на полке телефона
npm run check:craft    # placeholder — заглушки на витрине
npm run check:stage    # флаги настоящести (ворота 4), разметка и карта сайта (ворота 5)
```

Семьи описаны собранными таблицами: вёрстки и отрисованной — в `craft` (`checks.md`),
кода — в законе `code`; проверка без строки там — необъяснимое число, `check:rules`
это валит.

## Один факт о товаре — одно место

**Всё, что напечатано о товаре, спрашивается у данных**, а не набирается рядом с `id`
(цена в кнопке разошлась с корзиной). `twoTruths` в `check:css`, валит сразу ·
`references/facts.md`, «Цена в кнопке против цены в корзине».

**Вариант — это адрес, а не состояние** (профиль CBD витрины-образца; другая модель —
по брифу, `commerce-patterns.md`); переключатель без прокрутки, `scroll={false}`.
`jumpBack` · `facts.md`, «Крепость переключается переходом»; `references/blocks.md`,
«Переключатель варианта» · И465.

**Коллекция больше одного — маршрут с динамическим сегментом; ссылка на данные
литеральным id падает громко** (`?? notFound()`, не `filter(Boolean)`) · `facts.md`,
«Восемьдесят шесть карточек», «Мёртвая ссылка».

**Блок, обещающий факт, спрашивает флаг; условие — одной функцией на все места**, в
данных. `check:urls` · `facts.md`, «Блок, обещающий факт», «Условие пишется одной
функцией».

**Адрес — ключ, полем на каждый язык**; хвост товара — из слов названия, марка не
первой, папка одна (`/product/`) · `facts.md`, «Адрес — это ключ», «Хвост адреса».

**Данные согласны с собой** (имя против арифметики, подписи семьи различны). `npm test`
· `facts.md`, «Данные проверяются». **Производная величина — там, где ею отмеряют
дозу**; панель фактов — по предмету · `facts.md`, «Производная величина».

**Строка, повторяющая карточку глазами, ведёт на товар** — ссылка во всю строку ниже
органов · `facts.md`, «Строка списка» · И110.

## Наполнение — образец, пока заказчик не сказал иначе

**Публиковать образец как факт — отрицательное СЕО.** Флаги `ЧТО_IS_REAL = false`
(`lib/flags.ts`) спрашивают `offers`, `aggregateRating`, карта сайта, кнопка заказа;
флаги порознь, пока заказы закрыты — полоса «сайт строится». `check:stage` ·
`facts.md`, «СЕО-правка, публикующая образцы» · И792.

**Пустое состояние молчит.** Исключение — решение владельца: строка оценки у каждого
товара, без отзывов — пять пустых звёзд и «пока нет отзывов» · `facts.md`, «Пустое
состояние молчит» · И590.

**Заглушку печатают, нажатие — нет**: адрес канала считает одно место
(`telHref`/`mailHref`/`chatHref`, `lib/contacts.ts`). `placeholder`, `contactScheme` ·
`facts.md`, «Заглушку печатают».

**Отзывы — по праву** (`compliance.md`, п. 1): метод проверки раскрыт, verified только
с доказательством, звёзды на долю, сбор с первого заказа, образец — «Sample review» ·
`facts.md`, «Отзывы»; лента главной — `blocks.md` · И673, И728.

**Почта не печатается сборкой** — просьба владельца, в шаблоне не реализовано, открытый
пункт · `blocks.md`, «Почта, напечатанная сборкой».

**Слова магазина принадлежат владельцу и приходят из админки**; код держит запасное
содержимое по полю и не сочиняет назначаемое магазином · `facts.md`, «Слова магазина» ·
И173.

## Каталог и полка

**Плотность полки зависит от занятой ширины** — полная полка держит
4–5 простых карточек по 260–325px (максимум 340px), с панелью — 3–4 (профиль
витрины-образца); раскладка — `craft`. `catalogueColumns` · `references/catalog.md`,
«Полка: плотность, рельса, карточка».

**Рельса считает ширину от контейнера** (`--shelf-cols` 4, пол 240, потолок 340 —
профиль витрины-образца) · И501. **Карточка полки несёт то, что сравнивают**
(`factsLine`; подача `CARD_INFO` — выбор заказчика, шаблон `min`); наличие — только
исключением · `catalog.md`, «Полка» · И315, И316.

**Грань показывает только то, что меняет полку**: значения по рамке; не находит —
гаснет серым с «(0)», не скрыта; счёт — против всех граней, кроме своей ·
`references/cbd-facet.md`, §3, §7 · И317, И750.

**Полка — рамка, не галочка**: рамку называют заголовок и имя окна фильтра, «Сбросить»
снимает грани; выбранное — пилюлями, «применить» говорит живой счёт · `catalog.md`,
«Фильтр полки: рамка, выбранное, счёт» · И734, И740.

**Вид фильтра — глазами заказчика из всех видов, не по числу граней.** Основа —
`components/Filters.tsx` (шторка от края); варианты — на этапе изготовления; вида
«панель под строкой» нет и не предлагать · `catalog.md`, «Фильтр полки: виды на выбор»
· И739.

**Фильтры живут в адресе всегда**; комбинация — `noindex`, `canonical` на родителя, в
поиск поимённо по покрытию и спросу · `catalog.md`, «Фильтры каталога в адресе».
**Порядок — четыре пункта, кнопка знаком; листание — ссылками** · `catalog.md` · И709,
И721, И754, И758.

**Признак в навигации — своим адресом**, без адреса не выносится; выход ряда — к
существующей странице; устройство сравнивать только с магазином того же устройства ·
`catalog.md`, «Признак, вынесенный в навигацию», «Выход ряда» · И678.

**Блок под сеткой — единственный написанный текст полки**: прямой ответ первым,
лишнее прячет CSS, `FAQPage` из того же объекта, только на чистой первой странице;
вопросов — по норме страницы (профиль). `faqPage`, `tests/shop-copy.test.ts` ·
`blocks.md`, «Блок под сеткой», «Сколько вопросов» · И719.

**Полки на главной — кнопками героя** · `catalog.md` · И683, И735, И595. **Выдвижное
меню — названия полок**, служебное вниз · `blocks.md`, «Выдвижное меню» · И478, И479,
И772.

**Крошка = марка + имя + отличающий признак**; `h1` — только имя; на телефоне — шаг
назад к родителю · `facts.md`, «Крошка»; `blocks.md`, «Цепочка крошек».

## Карта товара и корзина

**Кадр приклеен ко дну строки покупки** раскладкой; **галерея помещается в экран**.
`sticky`, `stretch` · `blocks.md`, «Кадр приклеен», «Галерея» · И278.

**Кнопка покупки без выбора не выключается** (`choose=1`, ошибка у группы) ·
`references/cart-checkout.md` · И284. **Порядок карты — разделы подряд, без вкладок**;
стандартный вариант выбран сам · И466, И468, И473.

**«В корзину» говорит, сколько уже в корзине**, число из корзины. `check:counters`,
`tileGrow` · `cart-checkout.md` · И469, И763, И464, И764. **Счётчик один на сайт** ·
И331.

**Шторка корзины — товар, а не сводка; тот же лист, что меню и фильтры**; код скидки
свёрнут; смена количества без пересборки (`actionRedraw`) · `cart-checkout.md`,
«Шторка корзины» · И49, И63, И69, И671, И692, И693, И696, И772, И333.

**Строка корзины одна на шторку и страницу** (`CartLines`, упаковка `lineFacts`) ·
`cart-checkout.md` · И668, И688. **Полоса до бесплатной доставки — из данных**; нет
порога — нет полосы · `cart-checkout.md` · И668.

**«С НДС» — сноской, по обычаю, не по закону; сердце — на снимке полки и у «в
корзину»** · `cart-checkout.md`.

**У кнопки заказа — обещания из данных; пустая корзина — тихие строки к полкам, не
тупик**; ссылка на полку кнопкой — одна на сайт · `cart-checkout.md` · И332, И111,
И689, И785, И687, И784.

## Кабинет покупателя

**Кабинет — слой торговли, сессия та же, что у корзины**; ни один ответ не выдаёт,
есть ли почта; гость на кассе ворот не встречает; вход — страницами ·
`references/account.md` · И771.

**Форма входа — стандартная**; Google / Facebook — под формой, только у названных
сервером, ход в `__Host-` cookie; пароль 8–72; личное — `noindex` · `account.md` ·
И780, И787.

## Обязательные страницы

**Ответ, которого ждут по имени — контакты, доставка и оплата, возврат, о нас,
условия, данные, — живёт своим адресом**, в карте сайта и с разметкой · `catalog.md`,

**«О нас» — факты, а не прилагательные**; факт по имени (`{uic}`) из данных один раз

**Право страны** — профиль рынка (`profile-market-ro.md`, `profile-market-bg.md`);
норма ЕС — `compliance.md`; знак закона и реестр cookie — данные магазина ·
`facts.md`, «Знак закона» · И791.

## Язык рынка и поиск

**Шаблон строится на английском, сдаётся на языке рынка** (`DEFAULT_LANG = 'en'`,
решение владельца 10.10.2026); тексты рынка пишутся на последнем этапе от его досье
(транскреация, `seo-content`), не переводом; к сдаче — всё, что читает машина; марка не
переводится. `glued`, `market`, `translated` · `facts.md`, «Основные страницы — на
языке рынка». Переключатель языка — `blocks.md`, «Выдвижное меню» · И501.

**Ссылка внутри сайта — без языка** (`hrefFor`), «вы здесь» — по адресу без языка ·
`catalog.md`, «Страница узнаёт себя» · И94.

**Каждая правка — и с позиции SEO и GEO**: своё имя, h1 и описание, h2 словами
покупателя, FAQ для покупателя, не ради значка в выдаче, факты текстом ·
`references/seo.md` · И503, И504.

## Магазин CBD: что здесь особенное

Профиль CBD.

**Ни одного здравного утверждения на витрине — намеренно**; порог THC не пишется как
«легально до X %»; категория товара — юристу · `pages.md`, «Чего не писать»; нормы
страны — профиль рынка.

**Лаборатория — процесс, а не слово**: кто, что, как часто, где посмотреть; блок
протокола спрашивает флаг `lab` · `pages.md`, «ради доверия».

**Сила — две шкалы и формула диапазонов** (`lib/source/bands.ts`,
`tests/traits.test.ts`) · `cbd-facet.md`. **Единицы переводятся там, где читают**,
знание — в данных (`Pack.unit`) · `facts.md`, «Производная величина».

## Что переезжает в новый проект

Скилл целиком — `tools/kit.mjs` везёт всю папку `.claude/skills/`. Тесты магазина (в
образце — `tests/traits.test.ts`, `tests/shop-copy.test.ts`; сторожей адресов и формы
текста в нём нет) и соглашения `lib/` (`*_IS_REAL`, `telHref`/`mailHref`/`chatHref`,
`hrefFor`) — код проекта, образец лежит в `templates/storefront` набора: новый магазин
заводит их по описанию отсюда в день первого товара, а не переписывает готовыми, потому
что они читают его данные.
