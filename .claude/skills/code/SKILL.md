# Архитектура кода

Парный скилл к `craft`: тот отвечает за то, каким получился **экран**, этот —
за то, каким получился **код**. Граница — по вопросу: дефект виден на
странице — `craft`; виден только сложением двух файлов — сюда. Каждое
правило заведено найденным дефектом (история — `references/defects.md`);
правило без проверки живёт до конца сессии.

## Где кончается этот скилл

Про устройство: где что лежит, что с чем связано, что повторено, что
разрослось, где живёт состояние. Не про наполнение (тексты, снимки, цены,
имена — работа заказчика). Правил о том, чего в проекте нет (своя база), не
пишут: правило, ссылающееся в пустоту, хуже отсутствующего. Профиль
витрины-образца (`templates/storefront/`): Next.js с сервером —
`output: 'export'` в `next.config.ts` не стоит, есть `app/api`, действия
сервера (`lib/actions`), тесты `tests/*.test.ts`; торговля идёт через движок
(`lib/source`: Vendure или образец).

| увидел | иди к |
|---|---|
| контраст, отступ, ширина, шрифт, прыжок вёрстки | `craft` |
| композиция, иерархия, ритм блоков, «некрасиво», «как у всех», «переделай» | `impeccable` по порядку из `CLAUDE.md` («Дизайн делается дизайнерскими скиллами»); разбор готовой страницы — `redesign-skill` |
| разбор бага по шагам, проверка перед сдачей, тест перед кодом | `systematic-debugging`, `verification-before-completion`, `test-driven-development` |
| «что дальше», «какой этап», новый скилл от заказчика, сдача | `stages` |
| повтор, разросшийся файл, состояние, границы слоёв | сюда |

## Порядок работы

1. **Прочитать `CLAUDE.md`.** Он старше кода и старше скиллов.
2. **Прежде чем писать функцию — поискать, нет ли её.** `grep` по имени
   бесполезен: копия называется иначе. Ищется по тому, что она делает.
3. **Сделать правку.** Разнимаешь длинный файл — переведи на новые дома и
   сторожей, которые читали его ИСХОДНИКОМ: оставленный на входном файле
   сторож не падает, он зеленеет навсегда (И182, семья `deadGuard`).
   Переведённого перечитать обратным ходом: он всё ещё умеет падать?
   Правишь файл скриптом — пиши его байтами или с `newline=''`: Python в
   текстовом режиме на Windows переписывает весь файл в CRLF (И771); git с
   `text=auto` это прячет, а сосед по дереву видит переписанный файл.
4. **Прогнать `npm run check:code` и `npm run check:lint`.** Долг не должен
   вырасти ни в одной семье и ни по одному правилу.
5. **Прогнать `npm test`.** Правка поведения начинается с падающего теста —
   так велит `test-driven-development`. Правка разметки правится вместе с
   тестами, которые держат прежнюю строку, — в наборе (`selftest/`) и в
   витрине (`tests/`); перед коммитом идут тесты обоих мест.
6. **Прогнать сканер по изменённым файлам** — `npx react-doctor <файлы>`, —
   если правка трогала состояние, эффекты или обработчики.
7. Дальше — проверки вёрстки из `craft`, если правка её касалась.

## Правила

Нумерация стабильна: на правило 5 ссылается `templates/storefront/lib/store.ts`.

### 1 · Одно и то же живёт в одном месте

После правки на вопрос «где это делается?» ответ один. Чинить по убыванию:
звать готовый хук или функцию → иначе вынести в `lib/` (расчёт) или
`components/useИмя.ts` (поведение с состоянием). Другое имя копии —
не оправдание: дублируется работа, а не название. **Семья `twice`** сравнивает
тела, не имена; почти-копию не ловит — её находит чтение. Разбор —
`references/defects.md#правило-1--одно-и-то-же-живёт-в-одном-месте`.

### 2 · Функция обновления состояния обязана быть чистой

Функция, отданная в `setState`, только считает новое значение из старого:
React вправе позвать её второй раз, и побочное действие внутри (`setTimeout`,
другой `set…`) удвоится. Текущее значение помнится ссылкой, обновляется до
`setActive`, не в `useEffect`. Сторож — **react-doctor** (уровень «ошибка»).
Пример «было/стало» —
`references/defects.md#правило-2--функция-обновления-состояния-чиста`.

### 3 · Файл, который не читается целиком, чинится вслепую

Порог 420 строк (**`longFile`**); у порога — 378 строк (**`nearLong`**, И743) —
файл раскладывают по работам сейчас, тем же поведением и теми же тестами, а
не льют новое в случайный файл рядом. Данные (словарь, каталог, нарезка
снимков, схема полей панели, набор значков) не считаются; словари языков
шаблона `lib/i18n/<язык>.ts` — по правилу `DICTS` (И771). Разбор —
`references/defects.md#правило-3--файл-читается-целиком`.

### 4 · Компонент, помнящий восемь вещей, — это восемь компонентов

Порог — 14 хуков в одной функции (**`manyHooks`**). Делить по предмету, а не по
длине: вынимается целое дело вместе со своим состоянием и разметкой, а не
«последние двести строк». Разбор —
`references/defects.md#правило-4--компонент-помнит-одно`.

### 5 · Память браузера идёт через склад

`localStorage` — данные: прямой вызов не расскажет подписчикам об изменении и
падает в приватном режиме. Склад витрины набора один —
`templates/storefront/lib/store.ts`; список складов — `stores` в
`kit.config.json`. Сторожит **`keep`**. Одно исключение: загрузочный скрипт в
`app/[lang]/layout.tsx` читает выбор темы до первой отрисовки. Разбор —
`references/defects.md#правило-5--память-браузера-идёт-через-склад`.

### 6 · Отпечаток на документе — не источник правды

Настройка, пережившая перезагрузку, лежит в складе; атрибут на корневом
элементе — отпечаток, фреймворк сносит его при перерисовке корня (язык в
адресе, направление письма, класс шрифта). Обе половины обязательны:
**читать — из склада** (атрибут — запасной ответ на первый кадр); **ставить
отпечаток заново — после каждого перехода** (скрипт до отрисовки идёт один
раз за загрузку, мягкий переход — не загрузка). Отказом от мягкого перехода
не чинить: человек остаётся там, где читал. Проверки по файлам нет — мерится
отрисованной страницей: переключение языка не сбрасывает атрибуты корня
(у семьи нет имени; оформление шапки — `craft`). Разбор —
`references/defects.md#правило-6--отпечаток-на-документе--не-источник-правды`.

### 7 · Запись не пересобирает чужую страницу (И696, И698)

`revalidatePath`/`revalidateTag`/`sessionChanged` в действии сервера
возвращает заново собранную ТЕКУЩУЮ страницу. Запись, у которой свой экран
перечитывает себя сам (шторка, кнопка «в корзину»), пересборку не зовёт;
странице нужно обновиться — по событию (`cart:changed` → `router.refresh()`)
и сверкой отметки при «Назад» (`cartStamp`). Пересборка — только с
`redirect` или пометкой «своя страница»; иное — находка **`actionRedraw`**.
Нажатие показывает итог сразу (`PendingOp`, как `useOptimistic`) и
сверяется с сервером; время нажатия мерить по
`performance.getEntriesByType('resource')`, а не на глаз. Разбор —
`references/defects.md#правило-7--запись-не-пересобирает-чужую-страницу`.

### 8 · Личное на общей странице — одним запросом и общим списком (И469)

Страницы каталога статичны; число «в корзине» у кнопки приходит тем же
запросом, что и счётчик шапки (`/api/cart` → `held`), и раздаётся всем
кнопкам списком в памяти (`lib/in-cart.ts`, `useSyncExternalStore`) — не
запросом у каждой карточки и не исходом своей формы (товар, положенный
раньше, не виден). Запись кладёт своё число сразу, перечтение сверяет.
Это не склад браузера: правда — у корзины на сервере. Своей семьи нет.
Разбор — `references/defects.md#правило-8--личное-на-общей-странице--одним-запросом`.

## Чем мерить

```
npm run check:code     # семьи по файлам, храповик
npm run check:lint     # линтер (oxlint), храповик по правилам
npm test               # node --test; ноль тестов — падение
npx react-doctor       # сканер React и Next.js, 60+ правил
```

Храповик, как `check:css`: падает, только если нарушений стало **больше**;
база — `tools/code-baseline.json` (`npm run check:code -- --update`).
React Doctor даёт места, а не приговор: находки — гипотезы, перед починкой
читается код. Тест, закрепивший разметку, правится той же правкой. Пороги
420 и 14 замерены на профиле витрины-образца; в проекте другого размера
пересматриваются числом (распределение по файлам, хвост), а не ощущением.
Подробности и перенос в новый проект —
`references/defects.md#checkcode-храповик-и-семья-glued`.

### `check:code` — семьи по файлам

Таблица собирается из реестра `tools/code-families.mjs` командой
`npm run check:rules -- --tables`; рукой не правится — разошлись, `check:rules`
красная. Семья `glued`: переводить склеенную строку нельзя — ключа в словаре
нет, и она уедет как есть; склеивать уже переведённое.

<!-- families:code -->
| Семья | Что ловит |
| --- | --- |
| `twice` | одно и то же написано дважды: тела совпадают, файлы разные |
| `longFile` | файл длиннее 420 строк — целиком уже не читается |
| `nearLong` | файл у порога: длиннее 378 строк из 420 — следующая работа в него не влезет; разложить по работам сейчас, а не обходным файлом рядом |
| `manyHooks` | функция держит больше 14 хуков — это не один компонент, а несколько |
| `keep` | localStorage мимо склада: без уведомления подписчиков и без защиты от приватного режима |
| `deadLink` | href="#" — обещает адрес, а уводит на верх страницы |
| `translated` | имя марки без translate="no" — автоперевод браузера его перепишет |
| `glued` | переводу отдали склеенную строку — в словаре такого ключа нет, и она уедет как есть |
| `mutSort` | sort переставляет чужой список, а не копию |
| `jumpBack` | переключатель варианта без scroll={false} — нажатие уносит в начало страницы |
| `inkLiteral` | цвет числом в разметке — знак не следует теме (проверка вёрстки туда не смотрит) |
| `deadStyle` | класс описан в стиле, но его никто не берёт — правило есть, а на странице его нет |
| `deadSetting` | настройка, которая ничего не меняет: у поля панели есть провод, а того, к чему он ведёт, в коде нет |
| `contactScheme` | адрес канала связи (tel/mailto/messenger) набран мимо lib/contacts.ts — второй источник правды об одном номере |
| `deadGuard` | сторож читает исходником файл, в котором остались одни перевывозы — он больше ничего не сторожит и молчит об этом |
| `actionRedraw` | действие сервера зовёт пересборку (revalidatePath, revalidateTag, sessionChanged) без перехода — его ответ несёт заново собранную ТЕКУЩУЮ страницу, где бы ни стояла кнопка (И696); пересборка — с redirect или с пометкой «своя страница» |
<!-- /families:code -->

Линтер — oxlint (ESLint не подошёл: `typescript-eslint` падает на TypeScript 7);
отчёт читается как данные (`--format=json`). Тесты идут через
`tools/check-test.mjs`: молчаливый «0 тестов» выглядел бы результатом.
