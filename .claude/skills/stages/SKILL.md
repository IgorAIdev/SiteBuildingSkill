# Этапы производства сайта

Диспетчер: КОГДА что применять и чем проверять. ЧТО говорят остальные скиллы — не здесь.

## Область применения

| увидел | иди к |
|---|---|
| этап, ворота, «что дальше», сдача, новый скилл от заказчика, аудит чужого сайта | сюда |
| маршрут работ: задача → структура → вид → сценарий → полнота → приёмка → сопровождение | `site-building` (`skills/site-building/references/production.md`) |
| CSS, раскладка, ширины, доступность, вес страницы | `craft` |
| цвет, роль цвета, контраст, тёмная тема, палитра | `palette` |
| кегль, ритм, поле, воздух, зазор, размер органов | `scale` |
| TypeScript, состояние, границы слоёв, повторы | `code` |
| товар, цена, полка, корзина, оформление, обязательные страницы, магазин CBD | `shop` |
| «некрасиво», «как у всех», «переделай», композиция, иерархия, ритм блока | дизайнерские скиллы по порядку из `CLAUDE.md`, «Дизайн делается дизайнерскими скиллами» (там порядок записан один раз); разбор готовой страницы — `redesign-skill` |
| стиль нового сайта, ощущение движения | `impeccable shape`; движение — `emil-design-eng`, `improve-animations` |
| разбор бага по шагам, проверка перед сдачей, тест перед кодом | `systematic-debugging`, `verification-before-completion`, `test-driven-development` |

Старшинство: `CLAUDE.md` проекта старше всего; проверки старше советов; этот скилл говорит, КОГДА
применять остальные, а не ЧТО они говорят.

**Этапы одни — П0–П6** (`skills/site-building/references/production.md`, там же единая таблица П0–П6 ↔
ворота 0–6 ↔ слои). Ворота 0–6 этого скилла — не вторая шкала, а машинные проверки внутри П-этапов:
строка `Этап производства:` в `CLAUDE.md` и реестр `tools/stages.mjs` называют ворота, маршрут работ
ведут П-этапы. Слои 0–19 внутри этапа — порядок зависимостей реализации, не очередь работ:
`docs/layers.md`, §2.

Предикаты ворот проверяют соглашения профиля витрины-образца. Сначала определить их применимость;
отсутствие наших имён файлов не доказывает дефект чужого сайта. Неприменимая проверка не считается
пройденной. Хуки Claude не исполняются автоматически в других агентах: запускать проверки явно и
учитывать фактическое покрытие.

## Порядок работы

1. Прочитать `CLAUDE.md`. В нём строка `Этап производства: **N · Имя**` — одно место, где записано,
   где проект находится.
2. `npm run stage`. Обычно запускать не надо: хук `SessionStart` в `.claude/settings.json` уже
   напечатал его в начале сессии. Нет брифинга в контексте — запустить рукой. «Что дальше», «где
   мы», «какой этап» заказчика — тоже он, пересказом простыми словами: что строится, что держится,
   что ждёт.
3. Работать скиллами текущего сценария. Этап подсказывает проверки готовности, но не запрещает
   применять необходимую инструкцию раньше: например, структуру адресов, доступность и ошибки формы
   при первом прототипе.
4. Быстрые проверки идут сами после каждой правки файла — хук `PostToolUse` зовёт
   `tools/hook-after-edit.mjs`: стили → `check:css`, код → `check:code` и линтер, данные → тесты.
   Красное приходит в ту же секунду; чинится причина, не число. Часть магазина меряется, пока её
   делают (`check:part`, закон 8).
5. Заказчик говорит словами — какие проверки под них, печатает хук; список — `node tools/checks.mjs`.
   «Проверь сайт полностью» — `npm run check:all`; «готово ли к сдаче» —
   `npm run check:all -- --final`.
6. Перед сдачей — остальные проверки этапа в напечатанном порядке: сборка, адреса, разметка,
   отрисованная страница, свип; `check:stage` среди них следит, чтобы пройденные ворота не разъехались.
   Затем сверка всего сайта (закон 9) и архитектурный разбор (закон 12). Список «проверить в конце» из
   `docs/open.md` читается первым.
7. В ответе сказано, ЧТО проверено (закон 13). Заказчику — только его половина ворот (закон 5).
8. Переход на следующий этап — короткий разговор, потом правка одной строки в `CLAUDE.md` (закон 5).

## Законы

**1. Правило, не ставшее проверкой, забывается в той же сессии.** Конец сессии переживают ровно две
вещи: файл, который читается раньше кода, и проверка, которая валит сборку; всё здесь построено на
этих двух. Вопрос «перенять или запускать» один: становится ли это проверкой в `tools/` — тогда она
держится вечно (`npm run check:all` локально, CI — только вручную); нет — это совет, и он
записывается как «прочитать один раз на этапе N». Семья: `check:stage`. Справочник — `references/intake.md`.

**2. Скиллы друг друга не зовут, и применённый не на своём этапе отвечает мимо.** Каждый выбирается
моделью по описанию, поэтому этап, на котором он просыпается, записывается в реестр и печатается
каждой сессии; измеримая половина становится проверкой. СЕО на образцовом каталоге публикует
выдумку как факт (`craft`), кэширование на статическом экспорте описывает сервер, которого нет.
Скилл, приносящий свои числа, воюет с `tokens.css`: берётся идея, не числа. Справочник —
`references/intake.md`.

**3. Семь ворот — порядок проверок, а не работ.** Таблица — профиль магазина на соглашениях набора;
для сайта другого типа выбирать применимые проверки, не добавляя ему корзину, языки или движок ради
прохождения таблицы. Сдать раньше настоящих данных нельзя — поэтому наполнение — ворота 4. Реестр с
предикатами и очередью — `tools/stages.mjs`, `npm run stage -- --all`. Справочник —
`references/gates.md`.

| ворота | имя | что строится | что должно держаться |
|---|---|---|---|
| 0 | Основание | три шкалы, примитивы раскладки (ворота спрашивают пять из двенадцати `styles/primitives.module.css`, `tools/stages.mjs`), три брейкпоинта, `CLAUDE.md`, храповики | шкалы и примитивы существуют файлом; `check:css`, `check:code`, `check:port` с базами; храповики валят `check:all` |
| 1 | Каркас | адреса, дерево маршрутов, язык адресом, данные в `lib/`, карта сайта и robots как механизм | `routes.mjs`, `app/`, `sitemap.ts`, `robots.ts`; `check:open`, `check:urls` |
| 2 | Вёрстка | блоки, страницы, ширины, темы, вкус, движение | `check:craft` с базой, `sweep`; четыре запрета вёрстки на нуле; итог свипа сказан заказчику словами (снимки — по его просьбе) |
| 3 | Поведение | корзина, фильтры, формы, состояния, склады, панель | семья `keep` на нуле; React Doctor разобран; действия отвечают |
| 4 | Наполнение | настоящие тексты, снимки, реквизиты — от заказчика | все флаги `*_IS_REAL` в `true`; заглушек `[X]` в `lib/` ноль; `placeholder` в `check:craft` ноль |
| 5 | Сдача | карта сайта и разметка открыты поиску, вес, скорость, доступность, внешний аудит, перенос на другие движки | `check:seo` на нуле; доступность в `check:craft` на нуле; поломки переносимости (`varGone`, `markupDrift`, `engineInShared`) на нуле; PageSpeed и Rich Results глазом |
| 6 | Жизнь | Search Console, замер после выката, слежение | `check:all` держит адреса и разметку (CI — только вручную); учётки заказчика |

**4. Подэтап (слой или шаг каркаса) имеет одно из четырёх состояний** — `✓` пересмотрено (с датой и
правилом, которым куплено), `○` есть, не пересмотрено, `✗` не начато, `□` решает заказчик
(`docs/gate.md`); «сделано» говорится только про `✓` (И223). Отчёт заказчику после подэтапа — тремя
строками, как печатает `npm run stage`. Порядок слоёв — `docs/layers.md`, §2 и `steps` в
`tools/stages.mjs`. Справочник — `references/gates.md`.

**5. Глазом смотрят двое, и их нельзя путать, а переход этапа — разговор, затем одна строка.**
Исполнитель — токены, структуру, поведение, замеры; заказчик — как выглядит витрина, что на ней
написано, чьи снимки и реквизиты; заказчику печатается только его половина (И206). Переход меняет,
что включено на витрине, поэтому сначала: «ворота держатся, вот что включится; переходим?»; «да» —
строка в `CLAUDE.md`. Семья: `check:stage` — храповик: пройденные ворота не разъезжаются (шкала с
нулевых ворот не исчезает на третьих, `*_IS_REAL` с четвёртых не выключается на шестых), стоит в
`check:all`. Справочник — `references/gates.md`.

**6. Заказчик говорит словами, команды — мои; дизайн — порядок, а не проверка.** Заказчик не помнит
команд и не должен; слова находят проверки через `tools/checks.mjs`, хук `tools/hook-on-prompt.mjs`
печатает подходящие сам, подсказка — не приказ. Вторую таблицу «слова → команда» не ведут.
Правка вида идёт порядком скиллов из `CLAUDE.md` (И271); `check:design` меряет механическую половину
справочников impeccable, `check:detect` — детектором на отрисованной странице (И310); вкус и
композицию меряет порядок скиллов. Справочник — `references/gates.md`.

**7. Обход страниц — только на сборке, не на сервере разработки** (дев-манифест Next рвётся, И775,
И774). `check:seo`, `check:urls`, `check:craft`, `sweep`, `check:engines`, `check:open` гонятся по
`npm run build && npm run serve` с `SITE=` на своём свободном порту, не по :3020 заказчика.
Справочник — `references/runbook.md`.

**8. Часть магазина меряется, пока её делают (И765).** Хук правки запоминает тронутую часть, хук конца
работы не отпускает, пока не прошла `check:part` (узкий `check:craft` + `check:counters`); находки
чинятся в той же работе. Витрина не показала правку или скрипт — сначала запуск и сервер, не код
(И751, И725); файл, едущий в магазин, имени команды панели не пишет (`panel: true`, `kit-self`).
Журнал `docs/rules.md` заморожен, ночное сжатие (И737) приостановлено. Справочник —
`references/runbook.md`.

**9. Сверка всего сайта — моя обязанность, без просьбы (И523).** Проверки меряют страницу против
правила, но не страницы друг против друга и не путь покупателя. После пакета правок вида и перед
сдачей сам, телефон и ноутбук, тремя проходами: (1) одинаковое одинаково — размеры текста замером,
одна роль один размер, в окне ничего крупнее его заголовка, марка не мельче текста (И561–И563);
(2) устройство и путь покупателя — `impeccable critique` по всем поверхностям; (3) сайт и
дизайн-система — одно (И605, `check:system`; с панелью — `check:look`, `check:choice`, И612).
Найденное мной чинится мной до сдачи; нашёл заказчик — дописывается сверка. Справочник —
`references/audit.md`.

**10. Чужой готовый сайт ставится только режимом аудита** — `node install.mjs --audit .`; обычная
установка на чужом сайте — потеря (И169). Затем `kit.config.json` (без него проверки молча
зеленеют, И168), проверки этапа числами долга; храповик из них делать или нет — решает заказчик.
Справочник — `references/audit.md`.

**11. Чужой скилл не «ставится», а разбирается** по шести вопросам, и результат — три записи:
строка в `parked`/`PLATFORM` в `tools/stages.mjs`, разбор в `docs/skills.md`, семья проверки в
`tools/`, если что-то меряется, — сегодня, не на этапе N. В `.claude/skills/` не кладётся то, что не
работает сегодня. Справочник — `references/intake.md`.

**12. Одна вещь — одно устройство (И480).** Перед сдачей, после правки, заводящей новый вид вещи, и
когда расхождение нашёл заказчик — архитектурный разбор в три параллельных чтения (органы и
поведение, цвет по ролям, данные и решения); его не заменяет ни одна проверка. Держат часть:
`twiceDrawn`, `jumpBack`, `colorOut`, `briefRefs`, `briefMeasured`. Справочник —
`references/architecture.md`.

**13. В ответе всегда сказано, ЧТО проверено** — не командами, а именами: «проверил вёрстку по
файлам, отрисованную страницу и съёмку по ширинам — чисто». Заказчик не должен гадать, смотрел ли
агент на результат или поверил диффу.

**14. Новый сайт начинается с П0** (`skills/site-building/references/production.md`). Строка
`Этап производства: **0 · Основание**` — ворота 0 — уже стоит в переносимом `CLAUDE.md`;
`npm run stage` показывает, какие ворота держатся, `check:stage` на воротах 1 не даст уйти без шкал и
примитивов. Порядок закладки словами — `docs/start.md`.

**15. Объём прогона.** В ходе правки отрисованные проверки — по тронутым страницам и основному языку
(`--pages`), файловые — полностью; полный прогон (`build`, `check:craft`, `sweep`, `check:engines`;
все языки, обе темы, личные страницы) — ночью и перед сдачей. Непроверенное по ходу руками — сразу строкой в `docs/open.md`, «Проверить в конце
партии». Справочник — `references/runbook.md`.

## Что переезжает в новый проект

| файл | что в нём |
|---|---|
| `tools/stages.mjs` | реестр ворот 0–6: предикаты, очередь `parked`, список `PLATFORM` |
| `tools/stage.mjs` | `npm run stage`, `npm run check:stage`, `--all` |
| `tools/kit-config.mjs` + `kit.config.json` | где лежит проект и как названы шкалы — одно место для всех проверок и предикатов |
| `tools/check-seo.mjs` + `tools/pages.mjs` | двенадцать семей разметки для поиска — по `out/` или по живому серверу (`SITE=`), храповик |
| `tools/check-design.mjs` + `tools/design-families.mjs` | механическая половина impeccable: разметка и стили вместе, семьи с источником в его справочниках, храповик |
| `tools/check-detect.mjs` + `tools/detect-families.mjs` + `tools/vendor/impeccable/` | детектор impeccable по отрисованной странице: сборка закреплена хешем, у каждого правила одна судьба, храповик по страницам |
| `.claude/skills/stages/SKILL.md` | этот файл |
| строка `Этап производства:` в `CLAUDE.md` | где проект находится |

Реестр переносится как есть. Его предикаты смотрят на соглашения набора — шкалы, примитивы, базы,
флаги `*_IS_REAL`, — а не на конкретный магазин.
