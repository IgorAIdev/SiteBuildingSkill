# Архитектурный разбор: одна вещь — одно устройство

Заведён 27.09.2026 (И480) словом заказчика: «как это кнопки имеют разное
поведение в разных частях сайта, это же логически абсурд. Ты можешь
системно перепроверить архитектуру скилла шаблона? Или когда и как это
сделать правильно? Потому что я нахожу элементарные ошибки». Первый разбор
нашёл пятнадцать мест, где одна вещь сделана по-разному: три рисунка цены,
три строки сообщения, два выпадающих списка, шесть записей нажатия, три
выбора языка, серые места, где таблица ролей палитры велит цвет.

## Когда

1. **Перед каждой сдачей заказчику** — вместе с `check:all`.
2. **После правки, которая заводит новый вид вещи**: новый орган, окно,
   полку, строку сообщения, вариант выбора — до коммита.
3. **Когда заказчик нашёл расхождение сам** — значит, разбор опоздал:
   проходится целиком, а не только названное место.

## Как

Три разбора параллельно, только чтение (агенты Explore), каждый отдаёт
список «вещь → её устройства с файлом и строкой → чем отличаются для
покупателя → единственный источник»:

1. **Органы и поведение.** Всё, что нажимают: кнопки, ссылки-кнопки, знаки,
   крестики, счётчики, фишки, сегменты, вкладки, «смотреть всё»,
   нумерация. Для каждого вида — кто рисует (`btn` / `go` / `glyph` /
   `chip` / `seg` / своё); состояния — наведение, нажатие (`--press-move`),
   выключено, занято (`aria-busy`), удалось («Added»), ошибка (`f.say`);
   формы — поле, подпись, ошибка, кнопка; всплывающее — окно (`pane`),
   раскрытие (`menu`).
2. **Цвет по ролям.** Таблица `palette/references/roles.md`, «Проверка
   полноты: элементы магазина»: элемент → предписанная роль → чем он
   покрашен → расхождение. И какие семьи сигналов не читает никто.
3. **Данные и решения.** Где решается «какой вариант, какая цена, какое
   наличие» (карта, полка, разметка поиска, быстрый заказ, корзина); одно
   деловое решение, посчитанное в двух местах; тесты, держащие прежнее.

## Что потом

Каждое расхождение — одно из трёх: починено (единственный источник, и где
можно — семья проверки, чтобы второе устройство не завелось снова);
записано в `docs/open.md` с причиной; отклонено с причиной (два устройства
по делу — например, «оформить» во всю ширину в колонке итога). Отчёт
заказчику — списком «было N устройств — стало одно», снимками.

Что уже держит машина: `twiceDrawn` (знак, движение знака, окно,
движение нажатия нарисованы на месте), `jumpBack` (переключатель без
прокрутки на месте), `colorOut` (краска мимо палитры), `briefRefs` (решение
вида без живых референсов), `briefMeasured` (кегли и отступы без замеров
в брифе, И507), `deadName`, «класс описан, но его никто не
берёт».
