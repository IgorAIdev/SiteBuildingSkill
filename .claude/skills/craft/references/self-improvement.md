# Скилл самосовершенствуется — и это механизм, а не обещание

Когда читать: хук в конце работы спросил, родилось ли правило;
`check:rules` покраснела; заводится новая проверка; скилл вырос. Устройство
своих скиллов (закон, разбор, описание) — `.claude/skills/README.md`, «Свои
— шесть»; куда кладётся новое — `SKILL.md`, «Новое правило: куда
кладётся».

## Помнить — не решение

**Правило.** Работает только то, что лежит в файле и срабатывает само: цикл
замкнут двумя исполняемыми концами (два раздела ниже).
**Почему:** заказчик — «скилл должен быть самосовершенствующимся»; сессия
начинается с чистого листа и повторяет соседний файл — так набрались 180
медиазапросов и 25 размеров шрифта; за месяц при `CLAUDE.md`, требовавшем
шкал, — 153 кегля в пикселях и 483 отступа. Сработала только проверка,
которая валит сборку и называет виновных.

## Проверка не живёт без правила

**Правило.** `npm run check:rules` (`tools/check-rules.mjs`) гоняется на
**каждом** этапе — правило рождается на любом — и сверяет:

| Что сторожит | Почему это дефект |
| --- | --- |
| у семьи проверки есть описание в скилле | число без объяснения снимут как вкусовщину |
| у проверки есть имя, «что сторожит» и слова-приметы | не позвать фразой — не позовут |
| правило называет дефект, который его купил | без причины — совет |
| закон (`SKILL.md`) ≤ 500 строк; называет каждый файл `references/`; ссылки живы; справочник > 100 строк — с оглавлением | см. README |
| таблицы семей в `references/checks.md` — из реестров | рукой разошлась на семь строк |
| число запретов одно в `CLAUDE.md` проекта, `CLAUDE.md` набора и `SKILL.md` | новый сайт получил бы восемь из десяти |

**Чем мерится:** храповик — долг в `tools/rules-baseline.json`, проверка
падает, только если он ВЫРОС; опустить планку — `--update`, поднять нечем.
**Почему:** первый прогон — 11 расхождений, восемь — семьи без строки в
скилле.

## Правка спрашивает про правило

**Правило.** Хук `Stop` (`tools/hook-on-stop.mjs`): тронут сайт, а скилл и
реестр правил — нет, — спрашивает, родилось ли правило. «Да» **всегда**,
если дефект нашли **глазом**; искали по всему дереву; неверно **на уровне
решений**; пришлось **мерить**, потому что код или спецификация обманули.
**Почему:** вопрос, не запрет — опечатка и данные правила не рождают,
отличить может только делавший; но спрашивает КАЖДЫЙ раз.

## Куда что кладётся

**Правило.** Адреса и рост (**в свой раздел; дубль переписывается, а не
дописывается** — не «в конец файла темы») — `SKILL.md`, «Новое правило:
куда кладётся». Закон (`.claude/skills/*/SKILL.md`) — применимо к чужому
сайту без правки; разбор (`.claude/skills/*/references/<тема>.md`) —
читается, когда правка про тему; `docs/decisions.md` — «решил так, потому
что»; `docs/open.md` — ждёт слова заказчика; `docs/rules.md` — замороженный
архив номеров И. Признак виден в файле — семья в `tools/check-css.mjs` или
`tools/check-code.mjs`; на странице — `tools/check-craft.mjs`; нигде —
правило законно, но живёт, пока его читают.
**Почему:** двадцать пять разборов лежали под «что переезжает в новый
проект» — новое дописывалось в конец.

## Делится по роду и теме, не по этапам

**Правило.** Роды текста — по README; разбор — по ТЕМЕ, не по этапам (когда
какой скилл просыпается, решает `tools/stages.mjs`). Общее с частным
разведено скиллами: экран — `craft`, код — `code`, магазин и CBD — `shop`,
порядок — `stages`; решения одного магазина названы таковыми. Закон упёрся
в порог — сперва уезжает оставшийся разбор, потом закон сжимается до
строки на правило со ссылкой в тему.
**Почему:** 3950 строк одним файлом грузились при каждой правке; числа рукой
разошлись с кодом четырежды; `shop` выделен, когда две тысячи строк про
товар грузились при правке цвета кнопки.

## Чего этим не поймать

`check:rules` сторожит **сходимость**, не полноту; хук — **факт записи**.
Правило от отписки не отличит ни один — поэтому **правило пишется вместе с
дефектом, который его купил**: не назван — правило снимут, и справедливо.
