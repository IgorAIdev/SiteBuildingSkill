Owner 03.10.2026, angry after the typography rework: «ты ж и в скилл пиши, что ты нового сделал, чтоб мы для других сайтов не мучались… и в других чатах попроси тоже, чтоб скилл обновляли новыми знаниями или переписывали неправильные… и в проверку закладывай… и в скилл все эти проверки добавляй».

**Why:** the kit is built to make the next shop without repeating today's pain; knowledge left only in code comments or the rules journal is lost for the next site, and a rule without a check is worse than none (CLAUDE.md).

Owner again 05.10.2026, after a phone review batch where only the rules journal got everything and the skills got half: «в скил внеси ряд правил что мы выяснили и сам это делай без напоминаний». Since then: every owner remark that ends in a decision (a fix, or a reasoned «leave as is» like the payment pills) goes into the owning skill reference in the same batch, before the report — not only into docs/rules.md; the report names which skill got what.

**How to apply:** at the end of every batch, without being asked: (1) write the new decisions into the owning skill (craft / scale / shop / palette / code / stages or their references/) with the И-number, rewrite outdated lines instead of adding a second version; (2) give every rule a check family and describe the family in a skill so `check:rules` stays green; (3) rules journal entry with «Источник:», number read from the tail right before writing (numbers collide between sessions); (4) also what I learned on the way, not only what the owner decided — a measuring trap (lines counted by letters, not the sign's box), the wiring of a feature (personal cart state on static pages → code skill), a stale check after an organ moved (→ stages); (5) when the owner asks, message the peer sessions (ListAgents → SendMessage) to do the same.
