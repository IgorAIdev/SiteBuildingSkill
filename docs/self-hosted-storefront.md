# Проверка двух витрин на собственном раннере

Workflow `storefront on our runner` запускается только вручную:
Actions → storefront on our runner → Run workflow → main.
Push и pull request не запускают проверки. В него входят проверки набора, тесты приложения и Look-панели,
production build первого и минималистичного профилей. Торговый источник —
sample; реальные заказы выключены. Код внешних pull request на собственном
раннере не исполняется.

По умолчанию выбирается доступный раннер с меткой `self-hosted`, без догадки об ОС.
Свой набор можно указать в repository variable `SELF_HOSTED_RUNNER_LABELS`
как JSON-массив, например `["self-hosted", "linux", "storefront"]`.
Раннер должен быть зарегистрирован для этого репозитория или доступной ему
runner group и находиться online; регистрация машины этим workflow не
выполняется. На ней нужны Git, Bash и доступ к npm; Node.js 24 ставит
`actions/setup-node`. Проверки выполняются в отдельной папке текущего run.

`queued` означает ожидание подходящего раннера, а не пройденную проверку.
Фактическое имя выбранной машины и итог проверяются в GitHub Actions после
запуска. Результат нельзя объявлять успешным до завершения job.

Workflow `kit` также запускается только вручную на `main` и только на
self-hosted раннерах. Его `self` использует `SELF_HOSTED_RUNNER_LABELS`;
браузерные задания `components` и `studio` требуют Linux и используют
`SELF_HOSTED_LINUX_RUNNER_LABELS` (по умолчанию `["self-hosted", "linux"]`).
На Linux-раннере заранее нужны системные зависимости Playwright и
`google-chrome` с рабочей песочницей; шаг `install --with-deps` требует
доступа к пакетному менеджеру. Устанавливать такие зависимости следует
на машине проверок. Проверка на второй ОС больше не запускается автоматически.
Прежний отказ `studio` не маскируется сменой расписания.

Оба workflow не используют GitHub-hosted runner и не расходуют их минуты.
Затраты на собственную машину и хранение артефактов остаются отдельными;
артефакты хранятся 7 дней. Шаблоны `templates/check*.yml` — заготовки для
других проектов, в этом репозитории GitHub их не запускает.

workflow проверяет полное приложение, а не только статический экспорт.
