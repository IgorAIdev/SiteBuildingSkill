# Проверка двух витрин на собственном раннере

Workflow `storefront on our runner` запускается после push в `main` и вручную
через Actions. В него входят проверки набора, тесты приложения и Look-панели,
production build первого и минималистичного профилей. Торговый источник —
sample; реальные заказы выключены. Код внешних pull request на собственном
раннере не исполняется.

По умолчанию выбирается доступный раннер с меткой `self-hosted`, без догадки об ОС.
Свой набор можно указать в repository variable `SELF_HOSTED_RUNNER_LABELS`
как JSON-массив, например `["self-hosted", "linux", "storefront"]`.
Раннер должен быть зарегистрирован для этого репозитория или доступной ему
runner group и находиться online; регистрация машины этим workflow не
выполняется. На ней нужны Git, Bash и доступ к npm; Node.js 24 ставит
`actions/setup-node`. Проверки выполняются в отдельной папке текущего run.

`queued` означает ожидание подходящего раннера, а не пройденную проверку.
Фактическое имя выбранной машины и итог проверяются в GitHub Actions после
запуска. Результат нельзя объявлять успешным до завершения job.

Исходный workflow `kit` сохраняет независимые проверки переносимости набора.
Его прежний отказ `studio` не маскируется новым workflow.

Предпросмотр дизайна опубликован через Sites:

- [Минималистичная витрина](https://cbd-storefront-preview.ihormatyshchuk.chatgpt.site/minimal/en/)
- [Первая витрина](https://cbd-storefront-preview.ihormatyshchuk.chatgpt.site/original/en/)

Предпросмотр доступен владельцу через аккаунт ChatGPT. Это экспорт страниц
для сравнения дизайна; заказы, поиск, фильтры и отправка форм не выполняют
серверные операции. Источник приложения и обоих профилей — этот репозиторий;
workflow проверяет полное приложение, а не только статический экспорт.
