# Правила вёрстки

Сжатое ядро: читается каждым запросом, поэтому только правила, без истории.
Полный текст — почему каждое заведено, чьим словом и каким дефектом, с
границами — `docs/claude-full.md`, те же заголовки; туда за строкой, когда
на правило опираются (И499). Универсальный процесс — `skills/site-building/SKILL.md`.

Этот файл читается раньше кода. Если окружающий код противоречит правилу
отсюда — прав этот файл, а код подлежит починке, а не подражанию.
**Правило, у которого нет реализации, хуже отсутствующего правила.**

---

## Вёрстка: десять запретов

Разбор каждого — скилл `craft`; семьи проверок в скобках.

**1. `font-size` в пикселях запрещён.** Размер из шкалы `--fs-*` и ролей
текста; нужного нет — правится шкала (`styles/scale.json` → `npm run scale`),
не число на месте.

**2. Ритм — из шкалы, геометрия контрола — от его высоты.** Между вещами —
роли `--air-*` / `--pad-*` / `--gap-*` из ступеней `--sp-*`; внутри контрола —
от его высоты, не течёт. `margin` — всегда ритм; исключение — оптика меньше
8px. Форма, тень, движение и состояния — тоже роли (`--r-ctrl`, `--sh-*`,
`--press-t`, `--state-*`; И228, И229).

**3. Три брейкпоинта, и ни одним больше:** `1080`, `820`, `560` — только
где меняется смысл раскладки; ступенька размера на шве — дефект. Каждый
шов записан в `tools/seams.mjs` (`breakpoint`, `deadSeam`, `seamStep`).

**4. У всего с `aspect-ratio` есть потолок** (`max-block-size`); кадр —
примитив `frame`. Исключение — пропорция от уже назначенной высоты.

**5. Число колонок вычисляется, а не назначается** —
`repeat(auto-fit, minmax(...))`.

**6. Компонент меряет свой контейнер, а не окно** — `container-type:
inline-size` + `@container` (`nodeWindow`, `sizeContain`, `fullVw`).

**7. Раскладку не пишут заново — её берут** из двенадцати примитивов
`styles/primitives.module.css`: `stack`, `cluster`, `switcher`, `rail`,
`prose`, `lede`, `pinned`, `sidebar`, `grid`, `sheet`, `menu`, `frame`.

**8. Слой выбирается по поведению.** Модальное — `<dialog>` + `showModal()`,
немодальное — `popover`; номер слоя — только у висящего всегда, именем
`--layer-*`. Escape, фокус и `::backdrop` — от браузера.

**9. Всё, что приклеено или открыто поверх страницы, помещается в окно.**
Приклеенная колонка — примитив `pinned` (`stickyCap`); окно и шторка —
тройка `styles/pane.module.css`: шапка стоит, прокручивается тело (И460).

**10. Контрол живёт в одном месте.** Знак — в одном файле знаков, устройство
и ответ на руку — в своём модуле; блоки контрол берут, а не рисуют
(`twiceDrawn`, `deadEffect`).

Следствие: раскладка не зависит ни от ширины, на которой её смотрели, ни от
длины текста, который в неё положили.

## Переносимость: одна вёрстка, любой движок

Три слоя: **общее** (CSS на классах, токены, значки, форма разметки),
**переходник** (Liquid, PHP, компонент — данные своего движка в ту же
разметку, без решений о виде), **данные** (страница за ними ходит,
компонент получает). Компонент не ходит в бекенд и не считает деньги;
валюта и пороги — в данных. Меряет `npm run check:port` (И248).

## Что проверяется автоматически

Храповики (падают, только если нарушений стало больше): `check:css`,
`check:craft`, `check:design`, `check:detect`, `check:seo`. Не храповики:
`check:open` (до сборки), `check:urls` (после). Остальное: `check:scale`,
`check:port`, `check:stage`, `check:rules`, `typecheck`, `build`, `sweep`
(41 ширина), всё по порядку — `npm run check:all`. Страницы для проверок —
из дерева маршрутов (`tools/routes.mjs`), настройки — `kit.config.json`.

**Это обязательный шаг перед тем, как отдать вёрстку заказчику:**
`npm run build && npm run serve`, затем `check:craft` и `sweep` — у агента нет
окна, промежуточные ширины видны только так.

## Витрина: как править шаблон

1. `npm run storefront` — ставит `templates/storefront/` в `.storefront/` с
   видом из `showcase/`, запускает на http://localhost:3020 и следит за
   правками.
2. Правится **шаблон** `templates/storefront/…`, не `.storefront/…`.
3. Проверки — в `.storefront/` её командами (`npm test`, `check:css`,
   `check:design`, `check:code`, `check:lint`, `build`; И399).
4. Выбранный в панели вид — `npm run storefront -- --save-look` в
   `showcase/`, дальше коммит.
5. Коммит и PR; влитие в `main` выкатывает витрину на cbdin.ro само
   (Coolify, приложение `skill-storefront`; `npm run storefront:server --
   --domain cbdin.ro`, И434). Настоящий Vendure — переменные окружения
   (`SOURCE=vendure`, `VENDURE_*`), ключи в репозиторий не идут.

## Этапы производства

Этап производства: **0 · Основание**

Строка выше — единственное место, где записан этап; переводится только
после разговора с заказчиком. Семь ворот: основание → каркас → вёрстка →
поведение → наполнение → сдача → жизнь (`tools/stages.mjs`, скилл `stages`,
`npm run stage`). Скиллы набора по вопросу: `craft` — экран, `palette` —
цвет, `scale` — размер и расстояние, `code` — код, `shop` — магазин,
`stages` — когда что. Закон скилла — до 500 строк (`check:rules`).

**Команды выше — мои, не заказчика.** Он говорит словами; проверки запускаю
я, быстрые — хуки после каждой правки, тяжёлые — я перед сдачей.

## Правила работы

**Отвечать простыми словами.** Заказчик не технарь: ответ по-русски, что
сделано и что видно, человеческими именами, а не командами; работа — снимком.

**Граница ответственности.** Как устроено и как выглядит — исполнителя,
решается без вопросов. Тексты, снимки, имена, реквизиты и какие блоки стоят
— заказчика. Механизм картинок мой, сами снимки — его. Дефект наполнения —
строкой в ответе и в `docs/open.md`, не убирать и не переписывать.

**Всё делается и с позиции лучшего SEO и GEO** — своя страница у каждой
продаваемой вещи, уникальные имя и описание, FAQ с разметкой, где страница
отвечает на вопросы покупателя (И503).

**Описание идёт порядком, а не складом** — сначала шаги, потом перечень
(И217).

**Дизайн делается дизайнерскими скиллами.** Любая правка вида — по порядку:

1. контекст — `impeccable context --target <файл>` (запускатель
   `.claude/skills/impeccable/scripts/impeccable`; PRODUCT.md, DESIGN.md, бриф);
2. `impeccable critique` по находкам `check:detect` и `check:design`; новая
   поверхность — `impeccable shape`;
3. референсы и замок — три-пять живых магазинов, бриф `docs/design/<поверхность>.md`
   (`briefRefs`); образец заказчика — первый референс (И474);
4. пространственный тезис письменно — что главное, где воздух, и одна вещь,
   которую запомнят;
5. команды по находкам — `impeccable layout`, `typeset` и другие;
6. `impeccable polish`: каждое решение — из референса, брифа или правила.

Где скилл предлагает своё, а набор решил иначе — прав набор (И271, И300, И496).

**Работа показывается отрисованной** — на проде: правка влита, заказчик
смотрит cbdin.ro сам. Отрисованное проверяю я, снимки заказчику — только
по его просьбе (И500).

**Присланный элемент — рисуется, а не встраивается** — в `elements/`, базовым,
в трёх состояниях, красками палитры, с именем; на витрину — вариантом панели.

**Выбор показывается глазами, а не списком** — на витрине, стендом или
снимком; числа рядом, выбирает заказчик глазами.

**Вопрос без показанного — это переложенная работа.**

**Панель настройки физически отделена от сайта.** Варианты живут в панели,
сайт хранит один опубликованный вид; панель снимается одной командой и
только словом заказчика (`check:look`, И277, И352–И354).

**Правка делается, а не обсуждается.** Спросить — только когда два
прочтения ведут к разной работе.

**Архитектурная находка идёт заказчику, а не в комментарий.**

**Делается только правильно — сразу, а не по вопросу заказчика.** Сначала
называется слой: краска → строитель палитры → роль; размер и расстояние →
строитель шкал → роль; раскладка → примитив; контрол → его модуль; значение,
цена, текст → данные. Нет возможности — расширяется слой, обход запрещён
(`colorOut`, И295).

**Опираясь на правило, приведи его текст, а не пересказ** — адрес и сама
строка; правило читается перед тем, как на него сослаться.

**Правило дописывается в тот же день, когда его выявил дефект** — в
`docs/rules.md`, с описанием поломки.

**Ветка и вливание.** Ветка `claude/*` → PR → проверки зелёные → merge
делает открывший PR. Правки копятся в одну ветку и уходят одним PR за
задачу; за PR не подписываюсь, вливаю по слову заказчика (И500). Токены
экономятся: правки принимаются и делаются разом.

**Минуты GitHub — деньги заказчика.** Всё гоняется локально до пуша, пуш —
один на готовую правку; CI — только на PR.
