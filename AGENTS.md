# Работа над SiteBuildingSkill

Это репозиторий набора, а не боевого магазина. Начните с
`skills/site-building/SKILL.md`; правила, которые действуют всегда, — `CLAUDE.md`
(Codex читает этот файл, Claude — `CLAUDE.md`; при расхождении прав `CLAUDE.md`).
Устройство набора после перестройки 10.10.2026 —
`docs/skill-restructure-plan-2026-10-10.md`.

Где что лежит:

- свои скиллы — `.claude/skills/{craft,palette,scale,code,shop,stages}`;
  авторский вход — `skills/site-building` (и `assets/seo-content`);
  установщик выпускает копии для Codex и Claude (по умолчанию свои скиллы;
  чужой архив — `--extras`; другой стек — `--skill-only`);
- выбранные UI-исходники — стенд `selftest/component-preview` (`npm ci`,
  `typecheck`, `build`, `verify`, `lighthouse`), в сайт не ставится;
- чужие скиллы в загрузке — `.claude/skills/README.md`; выведенные из
  загрузки — `vendor/skills/` (как вернуть — его README);
- инструменты — `tools/`, исследования — `research/` (снимки не правятся);
- решения владельца по виду — `docs/owner-decisions/` и `docs/decisions.md`;
- журнал `docs/rules.md` заморожен 10.10.2026: архив номеров И; новый урок —
  в свой раздел скилла-хозяина и в проверку, без нового номера.

Этапы — одна шкала П0–П6 (`skills/site-building/references/production.md`).
Строка «Этап производства» в `CLAUDE.md` и `npm run stage` — ворота набора 0–6,
машинные проверки внутри П-этапов; прототип следующего сценария можно делать
до закрытия ворот. Числа и цвета профиля витрины-образца — не требования к
каждому сайту. Подтверждения из `docs/gate.md` в новые проекты не переносятся.

Проверки — в Node 24: `npm run check:rules`, `npm run check:skill`, `npm test`,
`npm run check:css`, `npm run check:code`, `npm run check:port`,
`npm run check:scale`, `npm run check:palette`, `npm run pro:check`; переносимое
ядро — `npm run studio:check`, `selftest/studio.test.mjs`, `selftest/studio-pilot`
(`references/studio-runtime.md`). Отрисованные проверки — только на сборке;
днём — изменённые страницы, полный прогон — ночью и перед сдачей.
Lighthouse-бюджет ради зелёного теста не ослабляется.

Весь согласованный объём обязателен: требование → реализация → потребитель →
результат. Готовность скилла не равна готовности сайта. Отдельно сообщать, что
сделано в сайте, что улучшено в скилле и что не проверено.

Публикация (владелец, 10.10.2026): мелкие правки — ветка → PR → слияние сам,
особенно названные владельцем; свои находки — тоже, но в отчёте полужирным,
по пунктам 1. 2. 3. Явное «не публиковать» в задаче соблюдается.

CI: проверки набора запускаются только вручную на self-hosted runner владельца,
для доверенного `main`; публичные PR к серверу не подключаются; GitHub-hosted и
larger runner без нового слова владельца не возвращаются; отчёты — 7 дней
(`docs/self-hosted-storefront.md`). Приватность репозитория ради экономии не
меняется.
