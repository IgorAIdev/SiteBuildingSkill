# Работа над SiteBuildingSkill

Это репозиторий набора, а не боевого магазина. Начните с
`skills/site-building/SKILL.md`, свежим аудитом `docs/audit-2026-10-08.md` и текущим
планом перестройки `docs/skill-restructure-plan-2026-10-10.md`.
Предметные навыки и их справочники находятся в `.claude/skills/`;
инструменты — в `tools/`, исходные исследования — в `research/`.

`CLAUDE.md` описывает существующий профиль вёрстки. Его числа, специфичные
для магазина условия и выбранные заказчиком цвета не являются требованиями
ко всем будущим сайтам. При противоречии о порядке разработки используйте
цикл сценариев из `skills/site-building/SKILL.md`: этапы обозначают готовность,
а прототип и проверки следующего сценария могут развиваться параллельно.

Не изменяйте снимки `research/**` и лицензии сторонних скиллов при правке выводов.
Не переносите подтверждения из `docs/gate.md` в новые проекты.
Проверки запускайте в Node 24: `npm test`, `npm run check:rules`,
`npm run check:css`, `npm run check:code`, `npm run check:port`,
`npm run check:scale`, `npm run check:palette`, `npm run pro:check`.
Также `npm run check:skill`: целостность выбранных ресурсов, лицензии и ссылки.
Для переносимого ядра: `npm run studio:check`, `selftest/studio.test.mjs` и полный
цикл `selftest/studio-pilot`; инструкция — `references/studio-runtime.md` внутри скилла.
Выбранные UI-исходники: в `selftest/component-preview` выполнить `npm ci`,
`npm run typecheck`, `npm run build`, `npm run verify`, `npm run lighthouse`.
Стенд не устанавливается в сайт. Результаты CI и ограничения локального транспорта
отмечать отдельно; не ослаблять Lighthouse-бюджет ради прохождения теста.
Единственный авторский вход — `skills/site-building`; установщик выпускает
копии для Codex и Claude. По умолчанию ставятся собственные предметные скиллы;
сторонний архив — явно через `--extras`. Для другого стека — `--skill-only`.

Весь согласованный объём обязателен. Проверять цепочку требование → реализация
→ потребитель → результат. Готовность скилла не равна готовности очередного сайта.
Панель/сайт/проверки/экспорт используют один источник и движок. Master не очищается
разрушительно; выбранный сайт экспортируется отдельно с MD/PDF и происхождением.
`npm run stage` показывает текущие контрольные точки демонстрационного профиля,
а не степень универсальности всего набора.

Для визуальной работы откройте действующие стенды, затем проверяйте полный
сценарий в репозитории выбранного пилотного сайта. Указание владельца от
10.10.2026: небольшие исправления — ветка → PR → слияние выполняет сам агент,
особенно когда их просил владелец; исправления по своей инициативе тоже
допустимы, но в отчёте выделяются жирным и нумеруются 1. 2. 3. Это заменяет
указания от 06.10.2026 и 07.10.2026.

После каждого замечания владельца и обнаруженного дефекта улучшайте скилл
в той же итерации: уточняйте инструкцию, общий компонент или проверку;
не ждите повторения ошибки. Авторский источник — `skills/site-building`.
Фиксируйте отдельно готовность сайта, улучшение скилла и пределы проверки.

Расходы CI: по указанию владельца от 06.10.2026 проверки SiteBuildingSkill
запускаются только вручную на self-hosted runner, без автоматических запусков
после push или PR. Не возвращать GitHub-hosted или larger runner без нового
указания владельца. Ручной запуск разрешён только для доверенного main;
не подключать публичные PR к серверу владельца. Метки и требования машины
описаны в docs/self-hosted-storefront.md. Отчёты хранить 7 дней.
Не менять приватность репозитория ради экономии.
