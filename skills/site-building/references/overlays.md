# Формы в окнах: содержание, доступная высота и действия

Читать при создании и исправлении форм в диалогах и шторках. Это инженерный
контракт адаптации, а не требование конкретной библиотеки или чисел магазина.

## Общий компонент

1. Найти общий модуль окна в дизайн-системе и всех его потребителей, включая
   образцы, настройки и экспорт. Высоту, предел и прокрутку исправлять там.
   Место решает, какое содержание входит в тело и какие действия — в низ;
   отдельные CSS-исключения для каждой формы не заменяют общий контракт.
2. Короткая форма занимает высоту своего содержания. Не задавать ей произвольную
   фиксированную высоту или полную высоту экрана. Форма растёт при добавлении
   полей, ошибок и строк перевода, пока доступная высота позволяет.
3. Ограничить рост доступным пространством окна браузера с учётом вырезов,
   панели браузера и клавиатуры. У нижней формы оставить край страницы сверху;
   высота шапки сайта за модальным окном сама по себе не задаёт предел формы.
   Использовать динамический viewport; отдельно проверить поведение платформы
   при открытой клавиатуре — `dvh` не во всех браузерах учитывает её перекрытие.
4. При переполнении прокручивается тело с возможностью сжатия (`min-block-size:0`
   в flex/grid); заголовок, закрытие и основное действие остаются доступными.
   Общий низ окна держит действие целиком, без необходимости искать половину
   кнопки в конце прокрутки. Связанные поля оставлять в закреплённом низу только
   если для них хватает места; иначе прокручивать поля, оставляя действие.
5. Если на очень низком экране или при увеличенном тексте даже шапка и низ
   не помещаются, предусмотреть доступную прокрутку вместо обрезки. Нельзя
   скрывать поля, текст ошибок или уменьшать текст и цели касания ради укладки.
6. Полная высота допустима по задаче для навигации, большого редактора или
   боковой корзины; она не становится умолчанием для коротких форм.
7. Сохранить семантику, фокус, Escape, закрытие и возврат фокуса. Добавление
   товара обновляет предусмотренное подтверждение и счётчик; само по себе
   не открывает корзину, если такой переход не предусмотрен согласованным
   сценарием. Изменение геометрии не должно добавлять новые переходы.

Мобильная клавиатура может менять `visualViewport`, не меняя `100dvh`.
Если CSS-высота не следует доступной области, обновлять общие переменные
высоты и смещения через один контроллер `visualViewport`, с очисткой слушателей.
Поле телефона в длинной форме оставлять в прокручиваемом теле, основное действие
— в общем низу; при тесном экране низ тоже должен допускать доступную прокрутку.

## Проверка на живых потребителях

| Сценарий | Что должно наблюдаться |
| --- | --- |
| Короткое содержание | Окно компактно, лишней прокрутки нет |
| Добавились поля, ошибки или длинный перевод | Окно увеличилось до предела; ничего не обрезано |
| Содержание превышает доступную высоту | Тело прокручивается; закрытие и основное действие доступны целиком |
| Узкий телефон и низкий экран | Нет горизонтального скролла; элементы управления доступны |
| Открытая клавиатура и смена ориентации | Поле и действие не скрыты клавиатурой; высота пересчиталась |
| Увеличенный текст и safe area | Содержание можно прочесть, кнопки не попали под системную область |
| Все применения общего модуля | Формы, отчёт, видео, меню и корзина сохраняют своё поведение |
| Добавление товара | Товар добавился, подтверждение обновилось; окно открывается только предусмотренным действием |

Для дефекта приложить воспроизведение, прежний и новый результат на одинаковых
данных и условия проверки. Эта таблица — критерии будущей проверки, не запись
уже выполненного браузерного испытания.
